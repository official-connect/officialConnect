# Release preparation: 1.1.8 (17)

The owner requested publication on 30 October 2026 after the reliability and
analytics follow-up. Play Console was checked live: production is 1.1.7 (16),
last published 3 October, and the upload library contains no higher version.
The new production draft is release 12. Intended initial rollout: 25%.

## Scope

- Keep cached screens usable while updates and noncritical telemetry run.
- Preserve valid sections through malformed or incomplete updates, including
  the same account entered with surrounding spaces or different letter case.
- Bound the initial website connection and total update waits, release the
  browser on terminal outcomes, and distinguish recoverable login errors.
- Improve bounded failure categories and distinct affected-user reporting.
- Include the pending phone/tablet layout and support/settings improvements.
- Harden release tag validation and run Python reporting/packaging tests in CI.

The independent review found and patched the account-normalization issue,
legacy cache identity loss, unsafe workflow tag interpolation, missing manual tag/commit validation, and
missing Python test coverage in CI. No raw student credentials belong in the
release fixtures. A privacy regression fixture was changed to a synthetic ID.

## Evidence before submission

- Full Flutter suite: 186 passing tests after the final legacy-cache identity
  patch; the focused cache suite passes 11.
- Python suite: 33 passing tests, including release tag validation.
- Earlier native phone and tablet runs passed all three checks per layout;
  a fresh phone run is repeated for this release after the cache patch.
- Signing is configured locally; signing and Firebase material also exist in
  the repository's GitHub Actions secrets. No keys are committed.
- Final AAB/APK must be rebuilt after the final code patch, pass native-library
  and 16 KB alignment checks, and be submitted unchanged after verification.
- Required GitHub checks are `verify` and `history`; merge only after both pass.

The website refused HTTPS connections during this release check. The app's
native failure state was verified in the preceding follow-up, but a successful
authenticated scrape is still unverified today. Publishing these defensive
fixes does not establish that upstream connectivity has recovered.
